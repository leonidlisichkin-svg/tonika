# 2.3 Editor screen

**Roadmap:** Phase 2. **Needs Leo:** a look on his phone at the end.
**Spec:** [`docs/specs/web-editor.md`](../specs/web-editor.md), sections "The screen" (states
Empty, Controls, Working, and the copy bar of Ready), "Look", "Quality bar".

## Goal

Paste a script, press one button, watch the marked text arrive block by block, choose the engine
and what to mark, copy the result. No word-level interaction yet.

## Read first

The spec, in full. `web/src/core/` from 2.2. `docs/specs/api-v1.md`.

## Build

- The single screen in React: text field, engine picker from `/v1/engines`, mode picker,
  «Расставить ударения», progress by blocks, the result as paragraphs with stressed letters
  tinted, the sticky bar with «Скопировать» and «Скачать .txt», the demo banner.
- Blocks analysed one at a time in order; a failed block retries in place; results kept by key
  so an edit re-analyses only changed blocks.
- Changing engine or mode re-renders in the browser with no request.
- Styles from the spec's tokens; light and dark; 360px first.
- Strings in one file, Russian and English.
- Settings in `localStorage`, text in `sessionStorage`, every call wrapped in `try`.
- Tests: a smoke test that the screen renders and that a mocked `annotate` produces the expected
  final text for two blocks; pure logic stays in `core/` with its own tests.

## How Leo sees it

In the Codespace run `uv run tonika serve` and `npm run dev` (in `web/`). VS Code offers to open
the forwarded port: he opens it on the computer, then the same address on his phone while signed
in to GitHub. Ask him for a screenshot and what feels slow or unclear.

## Out of scope

Tapping words, the review walk, the dictionary sheet (all in 2.4). Deployment (2.5).

## Done when

A 30 000-character text is marked progressively and copied on a phone; the JavaScript bundle is
under 120 KB gzipped (print the size in CI); CI is green.
