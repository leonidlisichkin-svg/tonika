# 3.1 Example checks

**Roadmap:** Phase 3. **Needs Leo:** nothing.
**Spec:** [`docs/specs/dataset-loop.md`](../specs/dataset-loop.md), sections 1 and 2.

## Goal

A dataset anyone can add to needs a gate that cannot be argued with. `tonika data check` is that
gate: every rule in the spec, offline, with exact messages.

## Read first

The spec. `docs/DATA_SPEC.md`, `src/tonika/evaluate.py` (it already parses example records),
`src/tonika/text.py`, `data/README.md`.

## Build

- `src/tonika/data.py`: the record type, loading, and one function per check in the spec,
  returning problems as `(file, line, message)`.
- `tonika data check <path>...` in `cli.py`; exit code 1 on any problem.
- `tonika data import <marked.txt> --lang ru --origin editor --out <file.jsonl>`: converts
  sentences in the golden `.txt` notation into records with fresh ids. Seed data (3.2) is written
  this way.
- Update `docs/DATA_SPEC.md` with `origin` and `was`. Make `evaluate.load_examples` use the same
  record type.
- Tests: a passing file; one failing fixture per check with its exact message; the golden-overlap
  check against a temporary golden file.
- CI: the `check` job runs `tonika data check data/examples` (an empty folder passes).

## Out of scope

Collection, review, releases, training.

## Done when

Each of the spec's eleven checks has a test that fails without it, and CI runs the check.
