# 2.5 Docker image and hosting

**Roadmap:** Phase 2 exit. **Needs Leo:** the choice of hosting and an account. Ask first.

## Goal

The editor at a public address, so an episode can be prepared from a phone with nothing else open.

## Ask Leo before building

Explain the options in plain words and let him choose. As known on 2026-11-16 (check prices and
terms again; they change):

| Option | For | Against |
| --- | --- | --- |
| Hugging Face Spaces (Docker) | Simple, models are next door | Docker Spaces needed a paid plan; sleeps when idle |
| Google Cloud Run | Scales to zero, pay per use, generous free tier | A Google Cloud account with billing; cold start loads models |
| A small VPS | Predictable, always warm | A monthly cost, a server to look after |

Needs: about 2 GB of memory for the Russian models, 1 CPU. A new account or paid plan is his
decision (`CLAUDE.md`). Secrets go into the hosting's or GitHub's secret store, never the repository.

## Build

- `Dockerfile`: stage one builds `web/`; stage two installs `tonika[ru,api]` with uv, copies the
  static files, downloads the models at build time so the first request is fast, runs as a
  non-root user, starts `tonika serve --host 0.0.0.0`.
- A CI job that builds the image and checks `/healthz` and one real `annotate` inside it.
- A simple per-address request limit for the public instance (in-process is enough), with
  `TONIKA_RATE_LIMIT` to set it. Record the choice in `DECISIONS.md` and in the API spec.
- Deployment as a workflow started by hand (`workflow_dispatch`) or by the platform's own
  integration. `docs/DEPLOY.md` with the steps and how to roll back.
- A short privacy note on the page: what is sent, that nothing is stored.

## Out of scope

Accounts, API keys, paid tiers (Phase 6). The dataset endpoint (Phase 3).

## Done when

Leo prepares a full episode from his phone at the public address. Phase 2 is closed in the
roadmap, with the address in `README.md`.
