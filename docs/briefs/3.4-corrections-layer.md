# 3.4 Corrections layer

**Roadmap:** Phase 3. **Needs Leo:** nothing. **After:** 3.3.
**Spec:** [`docs/specs/decision-lists.md`](../specs/decision-lists.md), "The layer" and "Gates".

## Goal

Learnt rules override the Russian model where the examples are clear, and nowhere else. From
here on, an accepted correction changes Tonika's answer without retraining anything.

## Read first

The spec. `src/tonika/packs/__init__.py`, `src/tonika/packs/stressonnx.py`,
`.github/workflows/ci.yml`, `data/golden/baseline.json`.

## Build

- `src/tonika/packs/layered.py`: `LayeredPack(base, corrections)`.
- `get_pack(lang, "auto")` returns the layered pack when `data/models/<lang>.dl.json` is
  available, else the base alone. The model file ships inside the wheel.
- CI `models` job: evaluate the base pack and the layered pack on every golden set and post both
  numbers. Fail if the layered pack is below the base on any set.
- Tests: the spec's acceptance points 5 and 8, with `FakePack` and `ScriptedBackend` as bases.
- `DECISIONS.md`: the measured effect. Raise the floors in `baseline.json` if accuracy rose.

## Pitfalls

- A rule decided by `default` never overrides the model. Only real rules do.
- The `model` string must name both layers, or results stop being reproducible.
- If the layer lowers accuracy, the answer is better examples or stricter thresholds, decided on
  cross-validation. Never a rule aimed at a golden sentence.

## Done when

CI shows both numbers, the layered pack is at least as accurate as the base, and one new example
fixes its own context in an end-to-end test.
