# 2.2 Browser core

**Roadmap:** Phase 2. **Needs Leo:** nothing. **Spec:** [`docs/specs/web-editor.md`](../specs/web-editor.md),
sections "Stack", "The browser renders", "Blocks", "Choosing a reading".

## Goal

The logic of the editor, with no interface yet: a TypeScript `render` proven identical to the
Python one, block splitting, choosing a reading, and a typed API client. Small, pure, fully tested.

## Read first

The spec. `src/tonika/render.py`, `src/tonika/document.py`, `spec/intent-document.schema.json`,
`docs/specs/api-v1.md`.

## Build

- `spec/render-vectors.json` and a Python test that builds the cases and fails when the committed
  file is out of date. Cover every branch listed in the spec.
- `web/`: `package.json`, `tsconfig.json` (strict), `vite.config.ts` (dev proxy for `/v1`, build
  output to `src/tonika/server/static/`), `index.html` with a placeholder page.
- `web/src/core/`: `types.ts` (Intent Document), `render.ts`, `blocks.ts`, `choose.ts`,
  `api.ts` (`annotate`, `engines`, `languages`; errors carry the server's `code` and `message`).
- vitest: every vector; `joinBlocks(splitBlocks(t)) === t` for varied texts including one line
  over the limit; `choose` and undo; code-point safety with an emoji before a token.
- `.gitignore`: `web/node_modules/`, `src/tonika/server/static/`.
- CI job `web` as in the spec. `CLAUDE.md`: commands and layout.

## Out of scope

Any visible interface beyond the placeholder.

## Pitfalls

- JavaScript strings are UTF-16. Every offset in the Intent Document is a code point.
- Do not re-implement analysis or the dictionary in TypeScript. The browser only renders.
- Commit `package-lock.json`; CI uses `npm ci`.

## Done when

The Python test and the vitest suite both pass in CI on the same vector file.
