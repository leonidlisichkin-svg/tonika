# Distribution

Status: outline for Phase 4. Each item below becomes a brief in `docs/briefs/` when Phase 3
closes; write the brief first, as its own small pull request, and check every external API named
here against its current documentation, because these projects change quickly.

The aim of the phase: Tonika is one line away wherever text meets a TTS engine.

## 4.1 PyPI

- Name `tonika` (free on 2026-11-16; check again). Version from `tonika.__version__`, starting at
  `0.1.0`. Wheel and sdist built by hatchling; the wheel must contain `engines/*.toml` and
  `py.typed`.
- Extras: `ru` (stressonnx, pinned), `api` (FastAPI, uvicorn), `mcp`.
- Release: a tag `vX.Y.Z` starts a workflow that builds, runs the full CI, and publishes with
  PyPI trusted publishing (OIDC, no token in the repository). First to TestPyPI.
- **Leo does once:** create the PyPI account, enable two-factor sign-in, add the repository as a
  trusted publisher. The brief lists the clicks.
- Done when `pip install "tonika[ru]"` in a clean Codespace runs the proof command.

## 4.2 MCP server

- `tonika mcp` speaks the Model Context Protocol over stdio, extra `mcp` (the official Python
  SDK; a new optional dependency, already agreed in the plan).
- Tools: `annotate(text, lang="ru", target="acute", mode=None, dictionary=None) -> text` and
  `list_engines()`. Same arguments and results as the library; errors as readable messages.
- Done when an MCP client (Claude Code in the Codespace) lists the tools and annotates a sentence.

## 4.3 Voice-agent transforms

- `tonika.streaming.StreamAnnotator`: accepts text in arbitrary pieces, buffers to a sentence end
  (`segment.iter_chunks`), yields annotated sentences in order, flushes the rest on close. Never
  reorders or drops text; adds no more delay than waiting for the sentence end. Core code with no
  framework imports.
- Thin adapters as documented snippets and tested examples for LiveKit Agents
  (`tts_text_transforms`) and Pipecat (text filters / transforms). They live in `integrations/`
  and are not dependencies.
- New presets, each marked `unverified` until someone has listened: ElevenLabs, OpenAI TTS.
  A preset records only what was checked against documentation or by ear.
- Done when a streamed paragraph, cut at random places, comes out identical to `annotate` on the
  whole paragraph (a property test), and both adapters run in their frameworks' example apps.

## 4.4 npm client

- A small TypeScript package: typed `annotate()` over the HTTP API, the Intent Document types,
  and the `render()` already written and vector-tested for the web editor
  (`spec/render-vectors.json`).
- **Ask Leo:** the npm account and the package name (`tonika` was free on 2026-11-16).
- Done when a Node script and a browser page annotate text against a running server.

## 4.5 Documentation site and accuracy table

- A static site built from `docs/` and published with GitHub Pages (no new service). The
  generator is a development dependency: **ask** before choosing it.
- Pages: quick start, engines and notations, dictionary, API, Intent Document, how to contribute
  an example, how to add a language.
- A public accuracy table generated by CI from `tonika eval --format json`: per language, per
  model version, per data release. Never edited by hand.
